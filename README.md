# Task Tracker CLI

## Описание

Task Tracker CLI — консольное приложение для управления списком задач.
Приложение позволяет создавать, обновлять, удалять задачи и изменять их статус.
Данные хранятся в JSON-файле в локальной файловой системе.

---

## Функциональные возможности

Приложение поддерживает следующие операции:

* добавление задачи
* обновление описания задачи
* удаление задачи
* изменение статуса задачи
* просмотр списка задач
* фильтрация задач по статусу

---

## Структура задачи

Каждая задача содержит следующие поля:

* id — уникальный идентификатор
* description — описание задачи
* status — статус задачи (todo, in-progress, done)
* createdAt — дата и время создания
* updatedAt — дата и время последнего изменения

---

## Хранение данных

Все задачи сохраняются в файл `tasks.json`, который создаётся автоматически при первом запуске приложения.

Формат хранения:

```json
{
  "id": "1",
  "description": "Task description",
  "status": "todo",
  "createdAt": "2026-05-03T12:00:00",
  "updatedAt": "2026-05-03T12:00:00"
}
```

---

## Запуск приложения

Для запуска необходимо выполнить команду:

```bash
dotnet run
```

---

## Синтаксис команд

### Добавление задачи

```
add <description>
```

Пример:

```
add "Buy groceries"
```

---

### Обновление задачи

```
update <id> <description>
```

Пример:

```
update 1 "Buy groceries and cook dinner"
```

---

### Удаление задачи

```
delete <id>
```

Пример:

```
delete 1
```

---

### Изменение статуса

Установить статус "in-progress":

```
mark-in-progress <id>
```

Установить статус "done":

```
mark-done <id>
```

---

### Просмотр задач

Все задачи:

```
list
```

Задачи со статусом "done":

```
list done
```

Задачи со статусом "todo":

```
list todo
```

Задачи со статусом "in-progress":

```
list in-progress
```

---

### Завершение работы

```
exit
```

---

## Ограничения

* идентификатор задачи должен существовать для операций update, delete, mark
* описание задачи не должно быть пустым
* статус задачи может принимать только значения: todo, in-progress, done
* данные хранятся локально и не синхронизируются

---

## Обработка ошибок

Приложение выводит сообщения об ошибках в следующих случаях:

* некорректный формат команды
* отсутствие обязательных аргументов
* обращение к несуществующему идентификатору
* пустое описание задачи

---

## Архитектура

Приложение разделено на следующие уровни:

* Model — описание сущности задачи
* Service — бизнес-логика работы с задачами
* Repository — работа с файловой системой и JSON
* Program — обработка пользовательского ввода
